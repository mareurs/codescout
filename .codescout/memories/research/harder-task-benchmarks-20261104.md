# Harder-task benchmarks for code-intelligence tool evaluation (research 2026-11-04)

Question: which benchmarks are harder than SWE-bench-style single fixes, test whether navigation/search tools help coding agents, and could suit a Rust-heavy study. Method: 5 cheap haiku research workers (researcher MCP; 2 of 5 returned nothing: backend "No sources found" / empty summaries) plus the controller fetching primary pages with WebFetch (a small model summarises the page, so numbers are single-source; two pages were truncated). Nothing here was run or re-measured by us.

## Primary-source findings (fetched 2026-11-04)
- **Multi-SWE-bench** (https://arxiv.org/html/2504.02605v1, read chars 0-100000 of 120825). 1,632 instances, 8 languages. Rust: 239 instances in 10 repos (ripgrep 14, clap 132, nushell 14, rayon 2, serde 2, bat 10, fd 14, bytes 5, tokio 25, tracing 21); 66 easy / 126 medium / 47 hard (by annotator time estimate, not by filtering). Rust resolved rate, Table 4: 0.42-15.90 % across 3 methods x 9 (2025-era) models; best is MopenHands + Claude-3.7-Sonnet 15.90 % (same cell for Python: 52.20 %). Tokens and $ per issue ARE reported (Tables 7, 8; Rust GPT-4o $0.1155-0.1565 per issue). Contamination handling: not stated in the visible text. No retrieval-tool ablation in the visible text.
- **SWE-bench Pro** (https://labs.scale.com/leaderboard/swe_bench_pro_public_v2). Public 731 (V2: 642 tasks, 11 repos), held-out 858, private 276 from 18 proprietary codebases. Public/held-out repos are strong-copyleft (contamination barrier); V2 disables web tools in the agent phase (earlier open-network run: 32 of 642 trajectories called code hosts, 4 fetched the fixing SHA). Reference patch mean 107.4 lines / 4.1 files, median 55. Original public-set results ~23 % (GPT-5, Opus 4.1). V2 leaderboard now lists top entries at 90-98 % (Opus 5 + Claude Code xhigh 98.00; lowest listed Haiku 4.5 25.50), i.e. SATURATED for frontier models. Languages named: Go, Python, JS, TS; Rust not stated. No cost/token figures; scaffolds vary (Claude Code, Codex, mini-swe-agent).
- **SWE-Explore** (https://arxiv.org/html/2606.07297v1). The closest fit to a navigation-as-variable design. 848 issues, 203 repos, 10 languages, Rust 31 (3.7 %); drawn from SWE-bench Verified, Pro, Multilingual. Explorer returns ranked line ranges under a line budget, scored against line-level truth. HitFile: Claude Code 0.667, Codex 0.649, Mini-SWE-Agent 0.640 vs TF-IDF 0.140, Potion embedding RAG 0.088, BM25 0.079 (oracle 0.923). Downstream check (150-instance subset, fixed GPT-5.4 + Mini-SWE-Agent patcher, restricted context): Oracle 59.7, CoSIL 59.3, Codex 50.3, Mini-SWE-Agent 50.0, Claude Code 48.0, TF-IDF 26.0, RAG 23.3, BM25 12.7, Random 4.7. Caveats: whole explorer SYSTEMS are compared, so tool and scaffold are confounded; grep is not a separate explorer; no decontamination steps; no token/cost figures.

## Secondary and low-confidence findings (worker reports, not re-verified)
- AgentConnect blog (https://www.agentconnect.md/blog/grep-beat-lsp-harness/; truncated, models and n unknown): models chose the semantic tool 0-6 % of the time on simple localization; forcing semantic-first cut success 100 % -> 89 %; LSP precision 1.00 vs grep 0.76 (recall ~0.66 both); Remeda: LSP added nothing, +16 % tokens; Hono: LSP F1 +0.246, -12 % tokens; multi-file rename pass@1 0.67 -> 0.83 with LSP.
- Preprints 202510.0924 (snippet only): LSP-augmented 117k tokens / 8 searches / 8 reads vs grep-only 108k / 7 / 6.
- FastContext (https://arxiv.org/html/2606.14066v3), own claim: trained explorer subagent, up to +5.5 % resolve and up to -60 % tokens on SWE-bench Multilingual / Pro / SWE-QA.
- Vendor and anecdote: Cursor says semantic search on top of grep gave +12.5 % accuracy on its own QA benchmark; Claude Code's creator said agentic search "outperformed everything" with evidence "mostly vibes" plus internal benchmarks; an unidentified "May 2026 study" reportedly found grep beat vector retrieval only when results go straight into context.
- Localization methods (no usable benchmark numbers): LocAgent / Loc-Bench (https://arxiv.org/html/2503.09089v1), OrcaLoca 65.33 % function match on SWE-bench Lite (https://arxiv.org/abs/2502.00350), RepoGraph (https://arxiv.org/html/2410.14684), SWERank Large 83.21 % Acc@1 file-level on Lite (secondary page only).

## Implications for the setup-ab study (my reading, not measured)
- A single-fix issue benchmark saturates (our own screen: 5 of 6 tasks passed by both models; SWE-bench Pro V2 now 90-98 % at the top).
- Candidates where grep alone should struggle: refactor / multi-file rename and cross-file reference tasks (AgentConnect rename result), large repos, and localization-only scoring à la SWE-Explore (HitFile / line recall, which does not need a patch to pass).
- Rust: Multi-SWE-bench Rust (239 instances; ripgrep, tokio, clap, nushell, bat, fd are repos we already use in Stage 1-3 images) is the best-covered Rust set, but its rates were measured on 2025 models and the instances are public (contamination not stated).
