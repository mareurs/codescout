## obscura-477 and the numTurns anomaly (investigated 2026-11-03, read-only, no spend)
- 477 fails in all 4 runs on the single F2P `dynamic_script_onload_fires$dynamic_external_scripts_execute_and_fire_load` (all four flags false). Verdict: UNDERSPECIFIED, not hard. The issue and its Puppeteer repro wait 5 s after goto. The gold test (test_patch, build/record.json) calls `dispatch` directly (no server) and needs a 600 ms script to finish before `Page.navigate` returns. The gold patch changes `Page`'s post-navigation settle loop (crates/obscura-browser/src/page.rs, `has_pending_dynamic_scripts`, default 3 s). Sonnet rep 1 fixed the idle-client case in crates/obscura-cdp/src/server.rs (pumps pages between CDP commands), which the gold test cannot see. Sonnet rep 0 touched only bootstrap.js. Opus reps 0 and 1 (diffs read 2026-11-03) chose the SAME design as sonnet rep 1: an idle event-loop pump called only from `cdp_processor` in crates/obscura-cdp/src/server.rs (rep 0: `CdpContext::pump_pages` + `Page::pump_event_loop` + `run_event_loop_slice`, 50 ms slices; rep 1: `pump_live_page`, 20 ms tick, plus `emit_js_network_events`). Neither extends the post-navigation settle loop, and the pump never runs inside `dispatch`, so the gold test cannot observe it. Opus rep 1 also fixed the nested/detached-container case (#422) in bootstrap.js (`_runScriptsOnInsert`); rep 0 did not touch bootstrap.js. page.rs edits in both reps only add helper methods (pump_event_loop, take_js_network_events). Three of four runs converged on the server-pump design; the fourth (sonnet rep 0) changed only bootstrap.js. Not checked: whether each agent's own test passed (both Opus tests and sonnet rep 1's go through the real server over WebSocket, `server::start` + `connect_async`, i.e. a path the gold test never uses; the agents' final messages claim success). wallMs is the harness clock around the whole CLI exec (run.py:1162-1164), so it includes the wait until the CLI exited and is correct as total wall time; the 1460 s vs 896 s gap for opus rep 0 is the post-result background wait (inferred from code, not timed). Treat 477 as a task whose test demands behaviour the issue does not state, not as a hard-task signal.
