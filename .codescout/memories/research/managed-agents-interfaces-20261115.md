# Anthropic "Managed Agents" (brain / hands / session): reference for agent and memory work (2026-11-15)

Reference note. Nothing here is built or planned. Read it with `research/agent-memory-frameworks` (what the memory landscape offers) and `collection-hot-view-state` (the first codescout piece that behaves like the "context outside the window" below).

## Source and its limits
- "Scaling Managed Agents: Decoupling the brain from the hands", Anthropic Engineering, 2026-04-08. Fetched from `https://www.anthropic.com/research/managed-agents` on 2026-11-15 with the WebFetch tool, which summarises the page through a small model. The quoted sentences below come from that result, not from a byte-exact copy. Re-read the page before you cite a quote in a spec or an ADR.
- The article describes a hosted service. It publishes interface shapes, not source code. codescout cannot "implement" the service. It can match or reuse the shapes.

## The model, in six lines
1. **Session** = an append-only log of everything that happened. It is durable and lives outside the harness and the sandbox.
2. **Harness** = the loop that calls Claude and routes tool calls. **Brain** = Claude plus its harness. It is stateless and replaceable.
3. **Hands** = sandboxes and tools. Each one is called through one shape: `execute(name, input) -> string`. The harness does not know whether a hand is a container, a phone or an emulator.
4. Recovery: a dead container is a tool error that Claude may retry (a new one is provisioned: "the container became cattle"). A dead harness restarts with `wake(sessionId)`, reads the log with `getSession(id)` and continues from the last event.
5. Context: compaction, trimming and memory files are all irreversible choices about what to keep. The session keeps everything and answers positional reads (`getEvents()`: resume, rewind, reread). The harness decides what enters the window. "The session guarantees only durability and availability for querying"; context management stays in the harness.
6. Security: credentials must never be reachable from the sandbox where generated code runs. Two patterns: vault-wired auth at provision time (Git clone token), and an MCP proxy that swaps a session token for the real credential. Narrow token scoping was rejected as the main defence, because it assumes the model stays weak.

Stated design principles: stable interfaces over implementations ("opinionated about the shape of these interfaces, not about what runs behind them"); components are cattle, not pets; do not encode assumptions about model weakness, because they expire (the Sonnet 4.5 "context anxiety" reset became dead weight on Opus 4.5); enforce security structurally.

## Where codescout already matches (each point read in code or memory)
- **codescout is a hand, and a store, not a brain.** There is no generative client in `src/` or `Cargo.toml` (verified 2026-10-19, in `research/agent-memory-frameworks`; not re-checked today). This is the article's split. Approach C of that memory (host-driven scaffolding) is the same stance: durability and querying in the server, generation in the host.
- **Durable logs exist.** The catalog table `events` holds `EventRow { id, artifact_id, kind, payload, anchor_commit, head_commit, author, created_at }` (`src/librarian/catalog/events.rs:7`). The table is audited (`src/librarian/catalog/audit/mod.rs:52`, `AUDITED_TABLES`). The audit shards are append-only lines `ShardLine { host, seq, at_ms, tbl, op, row_id, actor, verb, payload }` exported to `.codescout/audit/*.jsonl` (`src/librarian/catalog/audit/shard.rs:63`). `seq` is a positional cursor, with a watermark per repo.
- **A derived view outside the window.** The hot view (`codescout hot-view`) reads durable collection state and prints a bounded slice. The session-start hook, not the server, decides to inject it. This is "the harness shapes the context, the store only answers" in miniature.
- **A stable, thin interface.** The hot-view CLI contract (exit 0 = shown; exit 2 + `NOT SHOWN`; any non-zero = not shown, degrade open) is a small `execute`-like shape that a harness can call without knowing what runs behind it.
- **`@ref` buffers** are the working-tier version of "context as an object": a handle to a stored result that the model queries by path. They are in memory only (verified 2026-10-19: nothing is spilled to disk; not re-checked today).

## Where it does not match (gaps, not recommendations)
- **The per-actor read exists; the resumable forward read does not.** CORRECTION (2026-11-15, same day, after a closer read): the first draft of this note said no read of the logs existed. That was wrong. `librarian(action="audit_log")` (`src/librarian/tools/audit_log.rs`) queries `catalog_audit` by `tbl`, `row_id`, `actor`, `op`, `since`, `until` (epoch ms), newest first, `limit` default 50 and at most 500, with `truncated`, `filtered_total` and a `scope` block, and it merges other hosts' committed shards. `actor` is `codescout:<session-id>` (`resolve_actor`, `src/librarian/catalog/audit/mod.rs`), so "what did session X write" is already answerable. `doc(action="event_list")` reads one artifact's events (`since`/`until`/`kinds`/`limit`, `truncated`). The first grep missed both because I searched for a tool action named `events`. What is missing: a cursor. `audit_log` has no `after_seq`, no ascending order and no next-cursor, although `catalog_audit.seq` is `INTEGER PRIMARY KEY AUTOINCREMENT` (strictly increasing and never reused after a prune). Events are audited too (`AUDITED_TABLES` has `events`), so one cursor covers both logs. The log records catalog writes only, not an agent's reads or tool calls.
- **No `wake(sessionId)`.** A session resumes from trackers, memories and the hot view, all hand-written. Compaction in this session was exactly the irreversible choice the article describes. What survived was what we had already written to memory and trackers.
- **Pets exist in our own process.** Example from 2026-11-15: the git-ignored SDD workspace (ledger, briefs, reports, review packages) lives inside the worktree and dies with it. We kept only a summary in `collection-hot-view-state`. That workspace is a pet in the article's sense.
- **Credential isolation is not assessed here.** I did not check `run_command` against the article's "tokens never reachable from the sandbox" rule. Treat it as an open question, not a finding.

## How to use it (proposals; the operator decides)
1. **Keep codescout passive.** Do not build a harness or a brain. Offer hands and a durable store. This also fits the operator's positioning of 2026-11-15 (own skills, one thin Claude Code adapter).
2. **Test every new feature against the split:** does the server guarantee durability and querying only, with shaping left to the consumer? The hot view passes. A feature that decides what the model sees (for example an auto-injected summary written by a generative step) fails, and belongs in a hook.
3. **A cursor on `audit_log` is planned and PARKED** (`docs/superpowers/plans/2026-11-15-audit-log-resume-cursor.md`, status `parked`). An Opus review found that the tool surface has no room (budget log says headroom 0; the `librarian` description is 1,765 of 1,800 characters) and that `since` plus a client-side `seq` filter already covers today's volume (348 rows machine-wide in 24 hours, under the 500 limit; `truncated` says "capped"). Zero-byte recipe for now: `audit_log(since=<stored at_ms>, limit=500)`, drop rows with `seq <= <stored seq>`, read `truncated`. Unpark when a consumer is named; the plan lists what to fix first.
4. **Make state cattle.** Keep a durable copy of working state outside any worktree: the SDD ledger is the case that failed to qualify on 2026-11-15.
5. **Date our own harness compensations.** Rules that exist because of a model weakness (review escalation to Opus, "do not poll", compaction hand-offs) should carry a `revisit_by`, using the lifecycle collections, so that they are re-judged when the model changes. This is the article's "assumptions expire" principle applied to our CLAUDE.md rules. Idea only: no entry exists yet.
6. **Do not copy the service's credential patterns without a threat model.** If codescout ever proxies credentials, run `buddy:security-ibex` first.
