# Setup A/B: audit of how the codescout arms used codescout in the past study runs (2026-11-09)

Five read-only opus auditors (A-D by task group, E on structure/prompts) over study/runs (12 tasks, 108 runs: 52 bare, 28 cs, 28 full). Reports: job tmp audit/A.md .. E.md and BRIEF.md (not git). Controller verified these myself: pass rates bare 47/52, cs 25/28, full 22/28 (from run-record graderResult); "No such tool available" lines = 18 (14 full-sonnet, 1 full-opus, 3 cs-sonnet); `baseline.restore_paths` restores only dirs derived from gold's test files (ruff-15626 gold changed only snapshots, so agent-edited fixtures are not restored); all cs/full init events advertise 21 codescout tools incl. the 3 LSP tools.

Not invalid by the missing-languages defect (old tasks went through prepare_index). But the cs-vs-bare comparison is confounded:
1. Cost: cs 2.36x and full 3.28x bare (median), turns 2.1x/2.5x. First-turn context 7.4k (bare) vs 31k (cs) vs 43k (full), re-read every turn: 38-83% of the extra input tokens. Guard refusals are the second driver.
2. cs arm differs from daily/full: native Bash/Read/Edit stay in the tool list (arms.py:62,:453) and are blocked by the companion hook (43 blocks in cs, 6 in full; all 14 opus cs runs opened with a blocked native call); full has permissions.deny for Bash/Edit/Write and an explanatory output style. The hook's breaker let a native Edit through in ruff-15626 opus cs.
3. Guards refuse instead of hint: piped test in a `;`/`&&` list 54, multi-hunk edit_file touching a `fn` 30, line range overlapping a symbol 36 (74% of read_file calls pass force=true anyway), cat/sed on source 20. Turn ratio 2.09 -> 1.89 without wasted turns; the rest is smaller, more numerous calls.
4. Task CLAUDE.md reached no arm (known open issue, --setting-sources local; bug b8c35dc28bd3e8dd). Bare opus read it by tool call; cs/full mostly did not and hit the onnxruntime link failure (11 of 12 cs/full in cs-p01/04/07, 8 of 12 in cs-p08/15/19, vs 2-3 of 12 bare). Workspace activate also advertised build_commands ["cargo test"] and primary_language python for a Rust crate.
5. LSP/semantic tools unused: references 4, call_graph 0, symbol_at 0, semantic_search 0, memory/onboarding/get_guide 0 across 56 runs. Prompts are mostly prohibitions; the `references` description is one line, the "when to use" text lives only in long_docs. No evidence anything pushed agents to stop early (all 108 ended success).
6. Misleading results: `cargo test | tail` on a failed build returned exit_code 0 / passed 0 / empty stdout (producer_exit_code 101 only); sonnet calls codescout tools without the mcp__codescout__ prefix (hook text omits it); hooks tell the cs arm to call Skill(...) but it has no Skill tool.
7. Failures are not navigation failures: ruff-15626 is a grader artifact (agent-edited fixtures not restored); ruff-15309 cs passes are memorised gold comments (pre-cutoff task), full fails on a snapshot no tool could reveal; coreutils-6575 fails in all arms (output not byte-checked against GNU cksum; only opus bare.0 passed by comparing with od -c).

Hypotheses not verified: that fixing items 2-3 closes most of the cost gap; that the unprefixed names cause the sonnet errors; that references/call_graph would have prevented any failure (those tasks also fail bare).
