**Lesson:** When a **consolidation law** is declared anywhere — "kill via `platform::terminate_process`", "use libgit2, not a `git` spawn", "HTTP clients live in `codescout-embed`" — the highest-risk leak is an *existing* call site that predates the law and keeps the old inline pattern, especially in another file's `Drop` impl or the highest-traffic path. These leaks are *structurally* invisible to a diff of the declaring module, because by definition they live elsewhere in the tree. Declaring the law is cheap; the whole-tree sweep is the actual work, and the sweep is what gets skipped.

**Why:** The VDI reliability work stream leaked three times across two sessions. (1) Task 5 declared "kill processes via `platform::terminate_process` — no spawn" (Win32 `TerminateProcess`), yet `BackgroundKillGuard::drop` in `src/tools/run_command/inner.rs` still shelled out to `taskkill` — and in a *cancellation Drop*, where a stalled `CreateProcess` under EDR blocks cleanup, the worst place for the anti-pattern. (2) `shell_command_configured` was declared the single shell-spawn builder, yet the foreground `run_command` path built its `Command` inline on both platforms, re-duplicating sh -c / cmd raw_arg / GIT_PAGER / stdin / process_group / SIGPIPE. (3) A 2026-06-15 architecture review found a third: `legibility_scan::git_head` still shelled out to `git -C <root> rev-parse HEAD` (unbounded `.output()`, no timeout) after WIN-14 had converted the sibling `resolve_head_sha` to libgit2 — the git-spawn-elimination law reached the activation hot path but not the colder `src/librarian/` legibility path. All three leaks sat outside the file that *declared* the law (`src/platform/`, then `src/agent/`); each surfaced only via a whole-tree grep for the *old* pattern, never via the declaring diff — `git_head` lives in `src/librarian/tools/legibility_scan/`, nowhere near platform or agent. (4) 2026-07-25, a dependency-leanness review found a fourth leak in a *different law family*: `Cargo.toml` declares *"HTTP client and local ONNX embeddings are now provided by the codescout-embed crate"*, yet `retrieval::embedder::EmbedderHttp` still carries its own `reqwest` client — duplicating `RemoteEmbedder`'s OpenAI wire structs, its rustls provider install, and its `is_https_or_loopback` plaintext-API-key guard near-verbatim. The root copy's doc comment reads *"Mirrors the codescout-embed `RemoteEmbedder` guard"*: the duplication was known, annotated, and unenforced. The extraction converted librarian (`src/librarian/mod.rs:98`) and left retrieval; the bill was 48 crates compiled by two lean CI lanes that never call them. ADR `docs/adrs/2026-07-25-embedding-transport-boundary.md`. (5) 2026-08-16, a fifth leak in the sharpest form yet: BL-34 fixed a `parse` → mutate → `write` round-trip that reformatted hand-authored YAML, replacing it with a surgical line splice in `mv::repair_frontmatter_id`. The identical round-trip stayed live in `librarian/tools/update.rs` — the path `artifact(action="update", patch={"status": "archived"})` takes, which is the archive step this project's own `get_guide("tracker-conventions")` and `CLAUDE.md` mandate. What makes it the sharpest instance: the sibling was **not forgotten**. BL-34's own Fix section says *"Keep `update_in_place` for callers that want normalization (`artifact(update)`); it is the right primitive there"* — an exemption granted in the fixing document, from reading the code, never run. A six-call self-cleaning probe (write a hostile fixture, reindex, patch one field, `diff`, delete) settled it in about a minute: **one field patched, seven lines changed, six unrequested**, including `created: {YYYY-MM-DD}` → `created:\n  YYYY-MM-DD: null` — BL-34's exact destruction. Filed BL-36 (`861b565a934fcb2c`, commit `7b4e91cb`). A contributing cause worth naming separately: `frontmatter.rs` now holds two writers whose **names invert their contracts** — `update_in_place` sounds surgical and re-emits the whole block; `replace_id_line` sounds narrow and is the byte-preserving one.

**How to apply:** After declaring or changing a `platform::` function, grep the **whole tree** (not just `src/platform/`) for the *old* pattern it replaces — the raw syscall / shell-out / inline construction: `taskkill`, `tasklist`, `Command::new("sh")`, `Command::new("cmd")`, `std::process::Command` spawns, `raw_arg`, **and subprocess forms — `Command::new("git")`, `git -C`, `rev-parse`, `Command::new("go")`, `go env`, `.output()`**. `Drop` impls and timeout/cancel paths are the usual stragglers. Confirm every call site routes through the new abstraction before calling the consolidation complete. This generalizes past `src/platform/`: ANY "eliminate subprocess X, use library Y" decision (here, *use libgit2, not a `git` spawn* — convert to `git2::Repository::open(root).revparse_single("HEAD")`) leaks the same way, at sibling call sites doing the same op. Convert all siblings in the same pass — `resolve_head_sha`, `probe_has_git_remote`, and `git_head` are three such git siblings; WIN-14 converted one, F1/WIN-24 caught the third 6 days later. The replacement is not always a *library*: when the subprocess only computed a deterministic value (e.g. `go env GOMODCACHE`, WIN-25), re-derive that value from the environment — mirror the tool's own resolution order (`$GOMODCACHE` → `$GOPATH/pkg/mod` → `<home>/go/pkg/mod`), keep the deriver pure for the Linux gate, and accept the documented edge-case gap (an unexported `go env -w` override) as graceful source-not-found, never a hang. Second standing note: `platform::terminate_process` is **semantically asymmetric** — SIGTERM (catchable) on unix, forced `TerminateProcess` on Windows — so a caller wanting a hard, unignorable kill (e.g. an orphan-cleanup guard) must use `libc::kill(SIGKILL)` directly on unix, not the platform fn. Don't assume cross-OS parity behind a shared signature. Third standing note — **the tell differs by law family**. For subprocess-elimination, grep for a *syscall or shell string* (`taskkill`, `git -C`, `.output()`). For **crate-extraction** laws, grep for the old *type or module* (`reqwest::`, the duplicated helper's name) inside the crate that was supposed to stop owning it. Two cheap detectors that generalize across both: (a) a doc comment containing "mirrors", "same as", or "kept in sync with" is a co-change contract enforced by prose — strictly worse than compiler-visible duplication, because it proves someone knew and supplies no mechanism; (b) a feature flag whose *measured* cost is implausibly cheap (`remote-embed` measured **+1 crate** where it should be ~48) means the thing it gates is already unconditionally linked. Both are searchable in minutes, and both found real leaks here. Fourth standing note, from datapoint (5) — **a fix's own prose excusing a sibling call site is an unverified claim, not a decision.** When a bug file, ADR, or commit body says *"keep the old primitive at caller Y, it is right there"*, treat that sentence as the highest-value thing in the document to test, precisely because it reads as a considered judgement and therefore never gets one. The tell is scope asymmetry: the fix's evidence came from one caller, and the exemption covers a caller no evidence was gathered from. Same species as detector (a) — prose standing in for a mechanism — but harder to spot, because a doc comment saying "mirrors X" admits duplication while an exemption sentence asserts correctness. Cost to disprove is usually a **self-cleaning probe**: construct the hostile input the fix was about, drive the *excused* call site through the real tool (not the shared primitive directly), `diff`, delete. Six calls, no repo residue, and it converts an inference into a measurement — the only thing separating "I read the code" from "I ran it". Run a **negative control** in the same pass (here `librarian(action="reindex")`, which proved byte-identical) so the damage is attributable to one writer rather than to the flow. And when two primitives write the same field, check that their **names describe their contracts** — an inverted pair is what makes the next engineer reach for the wrong one by reading, which is how this leak was born. See [[outputguard-cross-cutting-law]] for the sibling "this is a law, not a helper" pattern, and [[tests-that-cannot-fail]] for the test-shape twin — a unit test on the primitive cannot catch a caller that routes around it.
