## IC-8 — a record asserts a completed action that nothing re-checked

**Slug:** `cluster/record-asserts-an-unchecked-completion`
**Claim:** A record states that an action completed, and nothing is scheduled to re-check it. The assertion is written at the moment of *intent* and read forever after as *outcome*, so a step that silently did not happen leaves a closure note that reads exactly like a successful one.
**Members:** `filter={"tags": {"contains": "cluster/record-asserts-an-unchecked-completion"}}` **New member 2026-09-02: `sendmessage-returns-success-for-a-message-held-for-approval`** — `SendMessage` returns `{"success": true, "… → <name>"}` for a message **held for the recipient user's approval and never delivered**. The return is a record asserting a completed action; the `[Cross-session delivery notice]` contradicting it arrives **asynchronously, one or more turns later**. **The variant worth naming, because it is not the class's usual shape:** here a re-check *does* eventually arrive — it is simply later than the window in which the assertion is acted on, which is functionally identical to none. Measured cost: a claim that a mutation window had been announced to a peer was committed at `8dee33a8` on the strength of the success return, and was false when written. The distinguishing test still holds — at the moment of use, nothing re-checks, and the tool offers no field distinguishing *accepted for delivery* from *delivered*. — `n=5`, 2026-08-31, by query after archive backfill. **A +1 was added and WITHDRAWN the same night, 2026-09-03**, and the withdrawal is kept rather than deleted because it shows how the wrong call gets made. `artifact-move-writes-a-stale-snapshot-and-leaves-the-source` (the slug it carried then; renamed 2026-09-04 to `pre-commit-stash-window-feeds-peers-wrong-bytes-or-enoent` once the false claim had been retracted everywhere — the old slug is kept here because this paragraph is about the filing as it was made) was filed here on the reading that `doc(action="move")`'s `moved: true`, its `history_grafted` count and its `stage_hint` were three assertions of a completed action that nothing re-checked. **They were all true.** `src/librarian/tools/mv.rs:75` is a bare `std::fs::rename` — the move happened, correctly, on the bytes present on disk; a peer's `pre-commit` stash window had transiently reverted those bytes to HEAD. The record asserted nothing false, so this class's claim is not satisfied and the member is withdrawn to `IC-12`, whose *transient shared state lies to every reader* fits exactly. **The tell, in hindsight:** the filing reasoned from the response being wrong without ever checking whether the response was wrong — which is this class's own failure mode, committed while filing into it. **+1: `refresh-prompt-stamps-the-version-before-the-work`** (2026-09-04) — `onboarding(refresh_prompt=true)` writes `onboarding_version = ONBOARDING_VERSION` to `.codescout/project.toml` and returns `"version_stale": false` at `src/tools/onboarding.rs:497`/`:513`, *before* the regeneration it only issues instructions for. The assertion is written at the moment of intent, exactly as the claim says, and the thing that would falsify it is the caller completing a subagent step. **Why it is a member rather than a near-miss:** the record does not merely go unchecked, it **destroys its own detector** — `onboarding_version_stale()` compares the stamped value against the compiled one, so the next `workspace(activate)` reports clean and no reader is ever told again. Observed live: `project.toml` at `onboarding_version = 30`, mtime 12:14, beside a v29 `.codescout/system-prompt.md` at mtime 10:25. **And the asymmetry is the sharp part:** the stamp lands in a *gitignored* file while the artifact it certifies is *tracked*, so `git status` shows nothing and each host certifies itself independently. **+1: `missing-file-counts-every-read-failure-including-non-utf8`** — the record here asserts a *cause* rather than a completion, which is the widening this member brings. `backfill_chunk_vectors` does `Err(_) => { report.missing_file += 1 }`, discarding the `io::ErrorKind`, while the field's doc states *"Artifacts whose file is no longer on disk"* and names a remedy conditioned on it: *"`librarian(action="reindex")` owns removal"*. Found 2026-09-07 by chasing the single artifact left vectorless after a full backfill: it is present, readable, 20133 bytes, and a **`.docx` carrying a `.md` extension** — ZIP magic `PK\x03\x04`, failing UTF-8 at byte 16 — so `read_to_string` returns `InvalidData`. The asserted remedy is inert for it *forever*: `reindex` removes rows whose file is gone, this file is not, so `NOT EXISTS` re-selects it on every run and the count sits permanently at 1 pointing at a repair that cannot apply. **The struct's own header argues against exactly this** — *"a file that is gone and a file that is empty are different outcomes with different remedies, and folding them into one number would make the report say 'skipped' about two unrelated things"* — reasoning applied to `skipped_empty` and not to the arm beside it. Count not re-derived for this +1. **+1: `install-hooks-writes-to-git-dir-so-a-worktree-install-reports-ok-and-does-nothing` (2026-09-09)** — and it sharpens the class's own framing, which says *nothing is scheduled to re-check it*. Here the re-check **was written, well, by the same author, in the same function** — and put on the arm that does not write. `install_shim`'s `--check` arm (`scripts/install-hooks.sh:242-266`) renders the shim into a `mktemp` and `cmp -s`’s it against the installed copy, which is a stronger verification than most guards in this repo get; the **install** arm below it (`:269-271`) runs `render_shim`, `chmod`, and then an `echo "ok  …  shim installed"` gated on neither, under a `set -uo pipefail` that omits `-e`. So the one path that mutates is the one path with no verification, and the omission is invisible precisely because the neighbouring arm is exemplary. **What actually fails:** `dest` derives from `git rev-parse --git-dir` (`:224`), which in a linked worktree is `.git/worktrees/<name>` — a directory with no `hooks/` — while git reads from `--git-path hooks`, the common dir. There is no `mkdir` in the file (grep: 0), so `cat >` fails, `chmod` fails, `ok` prints, and the script exits 0 having written **nothing**. **Second property, which no earlier member has:** the two arms disagree and each is *locally correct*. `--check` reports `MISSING` — true of the path it reads — and prints the remedy *"run without --check"*, which reports `ok` — true of nothing it checked — leaving the state unchanged, so `--check` reports `MISSING` again. A closed loop in which no step is wrong on its own terms; the shared premise is. Reachable today rather than theoretically: two peer sessions were live inside `.worktrees/` at 06:12:12Z, and a worktree session with no shim runs none of `pre-commit`, `post-index-change` or `pre-push` — the machinery that keeps concurrent sessions from capturing each other's work. Found while stress-testing an unrelated design; the first reading of it was that an *inert file* was written, which is the shape a reader would go looking for and would not find. The predicate is *"this sid is absent from `ack_matched`"*, which is satisfied by **no such author among the commits examined** and by **no commits were examined** — and the sentence asserts the first. So the note is a record written at the moment of intent (*I scanned and did not find them*) read forever after as outcome, and in the second state it is simply false. Its printed remedy — *"check you named the sid you meant"* — points at the reader's input under both, so the reassuring reading is the wrong one, which is what distinguishes this member from a merely silent record: it **misdirects the one party positioned to notice**. **Blind party:** the reader of the record, who has no signal distinguishing a verified closure from an asserted one. The author is not blind — they simply wrote what they intended to do.
**Promotes to:** `DC` — `docs/trackers/claim-decay.md`, whose `undecidable-green` and `premature-assertion` types already name this shape. This class is the bug-corpus entry point to that ledger, not a competitor.

Two of them cite this class by name as the reason they exist: `src/librarian/tools/doctor.rs:5597` (*"A record claiming a live owner with nothing re-checking it is `issue-clusters:IC-8`"*) and `src/librarian/session_registry.rs:5`. `terminal_status_with_caveat`'s own doc comment states the class's structure precisely — *"authors write the caveat, the canonical triage query filters on `status`"* — i.e. without the reader half, `unverified:` only moved an unchecked assertion from prose into frontmatter.

**What is still owed, and why this is `partial` rather than `shipped`:** every check above re-reads a **declared field**. None re-checks a closure stated only in **prose**, which is the shape of the one member below — a `## Fix` section asserting a `git worktree remove` in the past tense. No check opens that sentence, and `archived_fix_sha_unresolvable` deliberately skips freeform prose rather than sweeping it.
**Valid:** dated 2026-08-31

One member, kept because the instance is unusually instructive. `bench-worktree-deletion-recorded-as-done-never-happened`: an archived bug file is `status: fixed`, `closed: 2026-08-16`, and its `## Fix` section states the worktree *"was removed with `git worktree remove --force .worktrees/bench`"*, closing with *"174 MB reclaimed, 163 MB of it regenerable `.codescout` index state."* At filing the directory was **still on disk**, at 174 MB, of which 163 MB was `.codescout`.

**The directory has since been deleted — re-checked 2026-09-03** (`ls -d .worktrees/bench` → `No such file or directory`; `git worktree list` shows only `result-cap-marker-gate` and `tool-collapse`). **This paragraph read "The directory is still on disk. It is 174 MB" in the present tense until that re-check**, which is this very class holding about its own evidence: a true measurement, correctly taken, left under a verb tense nothing re-read. The instance stands — it was real on 2026-08-16 and the record was false when written — but the *evidence* is now historical, and a reader who re-runs the `ls` to confirm the class will find it refuted. Whoever verifies this class next: the artifact to check is the archived bug file's prose, not the filesystem.

**The numbers match the live directory exactly, and that is the finding.** They were measured — correctly — *before* the deletion, then written in the past tense. So the record is not fabricated and not sloppy; it is a true measurement placed under a false verb. No plausibility check catches it, because every figure in it is right.

This is filed as a class of one deliberately rather than folded into `DC`. The threshold is not met and it will not promote on its own, but the *bug corpus* is where instances arrive, and a class with a defined slug is what lets the second instance find the first. If it stays at one for a long while, the correct disposition is to retire it here and keep the analysis in `DC`.

**Falsified by** the closure note turning out to have been written after a deletion that was later undone, which would make it a lost-work bug rather than an unchecked assertion.
