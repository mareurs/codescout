## IC-24 — a value correct in one frame is published under a name that states another

**Slug:** `cluster/value-correct-in-a-frame-its-name-does-not-state`
**Claim:** A value is computed correctly in one frame — a coordinate space, a unit, a citation form, a time window, a scope word — and published under a name that states a different frame. The value is **exactly right and exactly recoverable**; only the binding between the value and its name is wrong. Every instrument aimed at the value confirms it, because the value is not what is broken.

**Blind party:** the **producer**, for whom the two frames coincide in every check they would think to run. This is the class's sharpest property and the reason *"verify before asserting"* is a no-op against it: re-verification returns the same correct value, and agreement is precisely what a correct answer to a neighbouring question produces. The body-relative test seeds the body and compares against the body. A session reading *who WROTE this path* off `scripts/file-provenance.py` and publishing it as *who STAGED it* gets a true sentence out of a tool whose output literally says `written by`. No instrument aimed at the value can read the name.
**Promotes to:** `not yet` — the count bar is cleared on creation, the spread bar is not adjudicated. Do not adjudicate it from the member list alone: three of the five axes were found in librarian-adjacent surfaces (chunk ranges, doc-ref counting, move reporting), one in git/CI reporting, and one in authorship tooling, which is a plausible three rather than a demonstrated five.
**Mechanism status:** `none yet`. The shape a mechanism would need is unusual and worth stating so nobody builds the wrong one: the defect is not detectable at the value, so a checker that recomputes anything will agree with the producer. What is checkable is whether a published quantity's **name** carries its frame — `total_is_lower_bound` does, `start_line` does not — which is a lint over output field names and prose labels, not over values.

**Why it opened at three members that were already in the file.** Three `cluster/unclassified` entries each close with a *"candidate class if a second appears"* note, and each names a **narrower** version of this one: `chunk-line-ranges-are-body-relative-but-published-as-file-lines` proposed *a quantity published in a coordinate space its name does not state*; `doc-tool-refs-counts-call-param-pairs-as-documents` called itself *unit-versus-label*; `a-move-reports-slug-and-path-citations-under-one-field-named-for-paths` proposed *a widened detector publishes its new population under the old one's name*. Coordinate space, unit, form — three authors, three axes, each asking for a second instance while two others already sat in the same file. **Nobody was wrong about their own member.** The generalisation is the frame itself, and it was invisible per-member by construction: from inside one axis the other two look like different bugs.

**The fourth axis, and the one that forced this open.** `embedder-stack-ops-session-log:F-7` — *a value that is CORRECT about a question you were not asked* — carries instances on the **scope word**: a sha correct for a real commit but not for *my push range*; a CI tally correct for one run but not for *the range*; one author correct for eight of nine staged paths. Its own analysis reaches this class's claim from the other direction (*"the defect is not in the value but in the binding between the value and the claim's scope word"*) without generalising past its axis, which is the same blindness the three members above show.

**That entry stood at three when this class opened and was corrected to six inside the hour** (`16575b1a`, `4df65ceb`) — so do not cite a count from here, read F-7. Two of the additions are not its author's, which matters: the axis is a property of the work, not of one session. **And the sixth differs in KIND from the other five, which is why it is named here rather than left in F-7.** The first five cost a wrong *fact*. The sixth named the wrong **pusher** in `d9d291b44775e50d` — a record about authorisation — at an instant when the operator so named had just decided to **hold**. A misattributed pusher in a file about authorisation does not merely misreport: it **manufactures a consent record from the one operator who withheld it**. Corrected at `4df65ceb`.

**The mechanism under that sixth is itself an instance, and it is measurable in one command.** `git reflog` records a ref movement and no session actor at all. Verified 2026-09-16 on `refs/remotes/origin/experiments`: three consecutive entries read `update by push` with `author=` and `committer=` **identical**, because the git identity is a constant across every session on this checkout. So the reflog's `author` field is a value correct in its own frame — the identity that made the ref move — published under a name a reader takes as *who pushed*. It is correct, and it cannot answer the question it appears to answer. **The pusher is therefore not derivable from the repository at all**: it is only ever a report from the session that ran the command. That is why the misattribution above was reached by adjacency in two dimensions at once — thread position, and the immediately preceding reflog entry — both pointing the same way, and neither carrying an actor.

**And the contrast is what makes that a finding rather than a lament, because a sibling question on this same repo DOES have an instrument.** `scripts/post-index-change-stage-log.sh:3` records *"WHICH SESSION staged each blob currently in the index"*, and `:37` settles the ambiguity explicitly — *"THE STAGER WINS, NOT THE FIRST OBSERVER"*. `.git/session-stage-log` holds `sid \t blob \t path` rows, verified 2026-09-16. So **staging** has an actor-recording instrument and **pushing** has none, which means the failure is not *"git cannot know who"* — it is that two adjacent questions have different answers and nothing marks which one you are asking. Measured the same afternoon: two sessions independently read a **stager** off `scripts/file-provenance.py`, which names **writers**, and neither reached for the stage log. One was corrected because the answer was wrong; the other was right by luck and drew no signal at all (`bug-fix-session-log:F-171`). **That asymmetry is this class's detection problem stated exactly** — an unsound method returning a correct value emits nothing for anyone to catch, so the population of these that get noticed is selected for being wrong, not for being unsound.

**Falsified by** a member whose value is *wrong in its own frame*. That is an ordinary computation bug, and this class claims the computation is right. Also falsified by a member whose true value is **unknowable** — see below.

**Held apart from `IC-20` by `IC-20`'s own falsification clause, which is also why these three were filed in the hatch rather than folded into it.** That row reads *"falsified by a member whose true total was recoverable — that is an ordinary reporting bug"*. There a walk **stopped**, so the true value is gone and the remedy is to rename the quantity as a floor or refuse to print it. Here every value is present and exact, and the remedy inverts: state the frame beside a value that is already correct. Each of the three members checked `IC-20` explicitly and rejected it on that clause; the hatch's contents are therefore this class's derivation rather than its backlog.

**Held apart from `IC-18`** (`selector-narrower-than-its-population`) on direction, per the Index file's own discriminator: `IC-18` sees **less** than its name claims, so the zero-reads-as-absent tell applies. This class's output is complete and correct — nothing is missing from it — so that tell cannot fire.

**Detector, on all four axes: a party holding the OTHER end of the binding.** The session whose commit it was knew which of theirs was outstanding; the session watching all three CI runs knew what the other two cost; the session that staged the ninth path knew it was not the eighth author's. None of those detections was available to a more careful re-measurement on the publishing side, and every one arrived as a correction rather than an alarm. **A SECOND BLIND-PARTY SHAPE, and it is not the one the field above describes.** Contributed 2026-09-16 by sessionId `9e022ef0-eb76-49f0-b175-4d68979290cf`, stated here as their derivation rather than paraphrased: `CODESCOUT_PUSH_ACK` is correct in the frame *"the pushing session's operator authorised this push"* and false in the frame *"the named authors agreed."* Both readings attach to one artifact — a list of sids in an env var, echoed into a trailer — and `scripts/pre-push-foreign-session-guard.sh` says in its own words that an ack *"is not a fourth author state"*, warning explicitly against reading it back later as agreement. It is this class rather than ordinary ambiguity because **every check aimed at the value confirms it**: the sids are correct, the derivation is correct, the authorisation is real, and nothing a verifier can point at is wrong. The falsity lives entirely in which frame a later reader supplies.

**What it adds is the direction of the blindness.** The `**Blind party:**` field above describes a producer who cannot see the gap. Here the producer saw **both** readings and said so to all five affected authors unprompted; the artifact simply cannot carry the frame forward, so correctness at production does not survive transmission. That is a second axis for this class — producer-blind and reader-blind are different remedies, since the first wants a check the producer would run and the second wants the frame travelling with the value.

**A THIRD VARIANT, and it moves the frame boundary INSIDE a single artifact.** Contributed 2026-09-16 by sessionId `9403d62d-116b-46ea-ac9b-004acff2b1cb` with the correction that produced it owed to `29420e72-c262-4236-82c2-52d769fdc549`. `bug-fix-session-log:F-168` publishes `22 processes: 14 stale and 8 clean` and concludes *the rebuild landed* — **correct**, because any process started after the binary mtime settles that, and the composition of the 8 is irrelevant to it. The same entry then closes with a remedy sentence over the same 14: *"any peer that has not reconnected is serving pre-rebuild behaviour until it runs `/mcp`"*. That sentence is **wrong** — one of the 14 is an LSP mux, which has no session to reconnect and exits by itself past its own `--idle-timeout`, so the population needing `/mcp` is 13. Same number, same entry, same author, correct in the headline and wrong in the remedy. Corrected at `7a986ac3`.

So the frame binds **per CLAIM**, not per value and not per document. An artifact that asks more than one question carries more than one frame, and only the sentence stating a **remedy** goes live — the descriptive sentence can hold the identical figure and stay true. That is finer than every member on the `**Members:**` line, each of which is one value under one name, and it defeats the obvious remedy of auditing an artifact's headline: the headline here was never wrong. **The first reading of this instance got it wrong in the coarser direction** — it called the conflation *latent in `F-168`, live in `F-170`*, which is per-entry — and the entry's own author falsified that by reading their closing sentence.

**SPREAD EVIDENCE, which is the bar this class has not cleared.** `**Promotes to:**` above records three of four axes in librarian-adjacent surfaces and calls the result *"a plausible two rather than a demonstrated four"*. Two instances from one afternoon sit outside that, in surfaces with no librarian component:

- **Process enumeration.** `scripts/stale-servers.sh` reports `servers=19 (13 stale, 6 current)` and `muxes=3 (1 stale, 2 current)` as two populations and prints **no combined total**, deliberately — it was reshaped 2026-09-14 after counting muxes as servers under one `total=`. Two sessions independently hand-walked `/proc` instead of running it and each published `22 / 14 / 8`. The arithmetic reconciles exactly (19+3, 13+1, 6+2); the frame is the **population**, and it matters because the two take opposite remedies — a server never recycles and must be reconnected, a mux exits by itself once idle. `bug-fix-session-log:F-170`.
- **Git plumbing unit.** Two sessions measured one diff at **73** and **40** within the same minute. `git diff <base> -- <file> | wc -l` is 73 — diff **output** lines, counting headers, `@@` markers and context. `git diff --numstat` is 32 added + 8 removed = 40 — **changed** lines. Both exact, neither recoverable from the other without naming the frame, and the mismatch presents as two instruments disagreeing about one file.

**The second cost nothing, and why is the closest thing to a remedy this class has produced.** Both parties had stated their **method** alongside their number, unprompted, so the mismatch resolved on inspection instead of sending either to debug a working instrument. `CLAUDE.md` § *Observer Blindness* position 3 says to ship a claim's derivation rather than its value — which reads as an obligation on a **writer**. This instance says it has to hold at **both ends of a channel**: either party omitting the method leaves the other with two numbers and no way to tell a frame difference from a defect. That is a reader-side duty the rule does not currently state.

**Recorded as VARIANTS, not as `+1:` members, on the rule the paragraph above establishes.** None of these is a tagged bug file — they are session-log entries — so putting them on the `**Members:**` line would break its correspondence with the tag census.
