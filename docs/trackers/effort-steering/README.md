# Effort-steering experiment index

## Read this first

This is the entry point for the effort-steering / low-quality-repair research. The goal remains a generic mechanism that improves low-effort repair quality to a useful reference level at lower complete-workflow cost. No generic mechanism has yet been validated by the latest development probes.

Only this index carries the current synthesis. The migrated notes below are historical snapshots: their old ACTIVE, NEXT, budget and resource-blocked statements are dated evidence, not instructions to resume old runs. Use the linked final reports before acting.

## Last recorded scientific state — 2026-11-08

- The baseline-only low/xhigh oracle pair retained the correct reference but accepted the saved wrong repair in both arms. This was a measured negative result on one exposed task, not evidence of general low/xhigh equivalence.
- One low uncertainty follow-up added observation work and a wholly successful-transform test, but left the important uncertainty unresolved and again accepted the wrong repair. All final offline cells were valid.
- The generic instruction did not ensure executable coverage of the uncertainty it named. Stop prompt tuning on this exposed case; a further study needs a distinct prospective mechanism and independently selected tasks.
- Last recorded known experiment-model subtotal: USD64.401093499999998654 plus the original unresolved USD4 startup reservation. This excludes any unmeasured orchestration/review cost. Original low plus follow-up USD0.5858154 is oracle-author cost, not complete repair-workflow cost.

## Roadmap and guardrails

1. Preserve the closed negative results; do not count incomplete-contract abstention or a green but non-discriminating test suite as repair success.
2. Before another paid study, register a materially distinct mechanism, its comparison and stop rule. Select tasks without looking at their outcomes; distinguish development from held-out validation.
3. Measure actual repair quality and complete-workflow model cost. Keep infrastructure-invalid results separate, reuse source-only onboarding, and preserve known/unknown spend on failures.
4. Keep new experiment journals and hand-backs here or in their canonical report. Project memory should retain only a short pointer to this index; generic project conventions belong in their existing shared memories.
