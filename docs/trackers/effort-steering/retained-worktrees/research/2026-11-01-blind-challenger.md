## What the challenger actually checked

Its first scenario nests a service under a fallback and asserts HTTP200. The handler obtains Option<MatchedPath> and formats it into the response body; the assertion selects only status with .0 and does not assert that the fallback has no matched path. Its second scenario asserts nested path concatenation equals /x/a/b. The test completes and passes on all three independently evaluated source roles.

The hidden parent control uses the public API to assert that Option<MatchedPath> is absent in a fallback. That control fails candidate and passes reference/gold. Thus the harness can express and detect the defect, while the blind proposal never asserts the missing invariant. This is an observed assertion gap; it does not prove why the model omitted it or that every low reviewer would do so.

The full transcript audit distinguishes ten repeated top-level tool-use blocks from five distinct request IDs after identical-input checks. It records one rejected shell-writing attempt, successful Write, and a successful source-bound Cargo invocation matching the final inventory. The model had real execution feedback and voluntarily ended below its allowance. Controls and unpaid shim invocations are not counted as model actions.

## Rulings and their costs

- Use the generic challenger, not another parent-hinted repair: otherwise we would repeat a mechanism already demonstrated instead of measuring discovery.
- One mutable explicit test target and frozen production: otherwise a reviewer could manufacture failures through unrelated edits or run no test.
- Retain V615e and prior ten sealed documents unchanged; no merge/push: otherwise historical evidence or peers' work could be altered.
- Reuse unchanged worker/evaluator/observer with phase-local bindings and prior public Rust gate evidence; scoped controls, mutation review and normal hooks remain required: a wrapper mistake can still invalidate the pilot, so no broad correctness claim follows.
- Preserve phase-local compatibility view and hidden cache alias after migration: incorrect path/isolation assumptions could invalidate source or blind exposure; no shared migration reversal was attempted.
- Interpret original survivor findings as Important and close them in one consuming-test pass; future discovery/repair, parity, billing and full core re-audit remain outside that review: confusing instrument confidence with efficacy would mislead the decision.
- Preserve original source capture and disclose the observer restoration rather than hiding it or paying again: otherwise attribution and costs would be corrupted.
- Stop B after no confirmed A counterexample; no sharper hint or model retry: otherwise outcome-driven tuning would replace the registered diagnostic.

## Implication and next discriminating question

We still lack an automatic missing-invariant detector. Another identical generic review is not justified by this result. A prospective follow-up should test a generic contract-to-assertion procedure: name preserved behaviors before judging the patch, turn each into an observed assertion, and use meaningful negative controls/mutations to reject tests that never observe their claimed property. That procedure must be specified before fresh cases and count all discovery, repair and escalation costs. This case can develop the mechanism, never serve as its external validation.
