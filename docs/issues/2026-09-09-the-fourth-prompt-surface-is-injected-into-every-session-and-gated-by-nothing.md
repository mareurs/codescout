## Summary

`.codescout/system-prompt.md` is the **fourth prompt surface**: tracked in git, generated by
`onboarding`, and injected into every codescout session in this repo at project activation. It is
covered by **no gate at all**.

`prompt_surfaces_reference_only_real_tools` (`src/server.rs:3680`) builds its `surfaces` list from
exactly three entries — `server_instructions.md`, `onboarding_prompt.md`, and
`build_system_prompt_draft`. The fourth surface is not among them, and no test file under `tests/`
so much as mentions `system-prompt`.

What stands in for a mechanism is a **policy**, in `CLAUDE.md` § *Docs*: *"Sweep it whenever you
sweep the other three."* The other three have a gate; this one has a sentence addressed to a
reader who must remember. That is `skill-frictions:SKF-22`'s lesson exactly — **a trigger the model
must notice is a policy, not a mechanism** — and `CLAUDE.md` § *Observer Blindness* position 3 asks
for the opposite ordering.

**Currently clean, and filed anyway.** No retired tool name appears in the file today, so this is a
latent gap rather than a live staleness defect. It is filed because the protection is absent, not
because the content is wrong: the three gated surfaces stay green while this one is served to every
session, which is the precise shape that makes a drift here invisible until an agent acts on it.


## Symptom (Effect)

A stale tool name, query, or rule in `.codescout/system-prompt.md` is served to every session in
this repo at activation, while all three `src/prompts/` surfaces pass their gate and CI is green.
The failure is silent in both directions: nothing reds, and the wrong guidance is delivered with
the same authority as the right guidance.


## Reproduction

Observed 2026-09-09 on `experiments`.

**1. The gate's population, read at the definition** (`src/server.rs:3680`):

```rust
let surfaces: &[(&str, &str)] = &[
    ("server_instructions.md",     crate::prompts::SERVER_INSTRUCTIONS),
    ("onboarding_prompt.md",       crate::prompts::RAW_ONBOARDING_PROMPT),
    ("build_system_prompt_draft",  draft.as_str()),
];
```

Three entries. `.codescout/system-prompt.md` is absent. The repo states this itself, in
`src/prompts/mod.rs:2498`: *"`prompt_surfaces_reference_only_real_tools` builds its `surfaces` list
from exactly three entries."*

**2. No test reaches the file:**

```
$ grep -rln 'system-prompt' tests/*.rs
(no output)
```

**3. Injected defect is undetected.** Appending `` Use `read_markdown` to read docs. `` to a copy of
the surface — `read_markdown` being a member of `DEPRECATED_TOOL_NAMES`
(`src/prompts/mod.rs:1959`) — produces a file that a scan finds (1 hit) and that **no test in the
workspace fails on**.


## Environment

`experiments` at the 2026-09-09 session; `cargo test --workspace` and
`cargo test --workspace --no-default-features` both exit 0 with the injected defect absent, and
would also both exit 0 with it present.


## Root cause

The gate is defined over the three surfaces that live in the **binary** (`include_str!`'d constants
and a builder function). The fourth lives on **disk in the repo**, generated and committed, so it
is reachable only by reading a file rather than a constant — a different kind of input, which is
why it was never added rather than deliberately excluded.

`CLAUDE.md` is honest about the count and names the fourth surface explicitly, so this is not
doc-vs-code drift. The defect is that the honest description is a **policy** where the neighbouring
three have a mechanism.


## Evidence

Scan of the fourth surface for every member of `DEPRECATED_TOOL_NAMES`, 2026-09-09:

```
find_symbol list_symbols replace_symbol insert_code rename_symbol search_pattern
read_markdown edit_markdown artifact_augment artifact_event artifact_refresh
  -> 0 hits
```

**That zero is a measurement rather than a broken grep, and only because of the controls.**

- *Positive control* — the same grep over the same file for live tool names returns
  `symbols` ×3, `read_file` ×1, `semantic_search` ×1. The method finds what is there.
- *Negative control* — injecting `read_markdown` into a copy is found (×1). The method finds what
  should not be there.
- *The finding* — that injection reds **no test**, which is the defect.

Worth recording separately, not as part of the claim: the file mentions `edit_code` zero times.
Not asserted here as a defect; noted so the next reader does not have to re-derive it.


## Hypotheses tried

- **Already filed?** `doc(action="find", kind="bug", semantic=...)` over the fourth-surface
  gating question returned 50 rows; the near hits are
  `4e4762b735deb392` (*the prompt-surface gate is backtick-scoped, so the Iron Laws are invisible
  to it* — a **scoping** defect inside the gate, over surfaces it does cover) and
  `44afbc18878be5d8` (*onboarding writes the system prompt to the memories dir* — a write-path
  defect, archived). Neither claims the fourth surface is ungated.
- **Doc-vs-code drift (`IC-11`)?** Rejected: `CLAUDE.md` states the count correctly and names the
  fourth surface. Nothing is contradicted; the mechanism is missing.


## Fix

Not applied. Two shapes, in preference order:

1. **Add the file to the gate's `surfaces` list.** Cheapest, and directly expresses the claim the
   gate's name already makes. It needs a read from disk rather than a constant, and a decision
   about the case where the file is absent — a fresh clone before `onboarding` has run. **Absent
   must not be silently green**: that is the monotone direction, and it is the state most
   repositories are in.
2. **Generalise to "every committed prompt surface"**, deriving the list rather than enumerating
   it, so a fifth surface is covered on arrival.

Shape 2 is what `IC-14`'s row asks for (*the mechanizable sub-shape is a name-to-predicate
comparison*) but is the larger job; shape 1 closes this instance.


## Tests added

None — nothing is fixed. The regression test must be **two-sided**, because an assertion that the
surface contains no retired name is monotone under the file being absent or unread: pair it with a
positive control asserting the scan finds a known-present live tool name in the same file, so a
path that reads nothing cannot pass.


## Workarounds

`onboarding(refresh_prompt=true)` regenerates the file from current templates — but note it must
follow `cargo rb` + `/mcp`, since `source.md` is `include_str!`'d and therefore frozen at build
time and again at process start. Refreshing before the rebuild produces a plausible, committed,
wrong artifact generated from the pre-fix binary.


## Resume

Pick shape 1 or 2 above, add the surface to the gate with the absent-file case decided explicitly,
and write the two-sided test. Demand an observed red by mutating the production path — inject a
`DEPRECATED_TOOL_NAMES` member into the real file and confirm the new test fails before reverting.
