# Local semantic decisions for codescout: evidence review

**18 September 2026 — decision brief for Marius.** The 17 September TypeSafe/Jev brief identifies a useful design pattern: ask bounded semantic questions, return typed values, and keep composition and consequential actions in application code. Codescout already assembles structural and historical evidence that could feed such questions. The investigation does **not** establish that Jev, a small local model, or any learned evaluator would improve codescout today. Within this bounded judgment study, the research choice is between (a) ranking useful precedents for an investigator and (b) triaging a specific claim against its named evidence or referent. These judgment components need frozen-case evaluation against rules, search, and human review; the broader execution design is addressed below. No model or pilot is selected here.

**Scope correction, 18 September 2026.** This report evaluates bounded Jev-like semantic judgments and the historical evidence available for them. Its recommendation to stop at advisory ranking was an overly narrow reading of the product goal. Marius's intended system can carry out selected investigations, tests, fixes, and multi-step tool workflows, with context delivered when it can affect the next action. A lightweight deep-agent runner may use a local model or an explicitly approved external LLM API. The current architectural direction, including capability and execution contracts, is the [deep-agent design](../trackers/local-semantic-evaluator-design.md). The measurements and corpus cautions below remain applicable; they do not veto autonomous execution.

The second task is distinctive: a prose conclusion can remain in place after a maintained count, member list, or code path changes. The first task is easier to define and score, but codescout's own retrieval history shows how often corpus coverage, chunk selection, or a source filter matters more than a new ranker. A third, narrower research question is whether a helper can catch an incident verdict whose observed result points the wrong way under an explicitly stated rival hypothesis. One corrected incident motivates that question; it does not show that a small classifier can solve it. These choices and their stopping conditions belong in the [living design brief](../trackers/local-semantic-evaluator-design.md). The [teammate feedback](../trackers/typesafe-jev-report-feedback.md) separates corrections to the original report from these new hypotheses.

## What was reviewed, and what changed

The corpus pass traversed the project-scope librarian catalog in pages and mapped tracker metadata and one-hop citations. It did not read every entry. Five subsequent investigations deep-read selected workflow friction, failure-lens, retrieval, evaluation, and product-boundary records. Selection was purposive: examples that might support a learned decision were paired with examples in which a deterministic repair or missing observation defeated that idea. This is neither a prevalence survey nor a model benchmark. No new training, inference test, retrieval run, mutation test, or user study was performed. Historical numbers below retain their own date, configuration, and denominator.

The original brief correctly presents Jev's state-plus-typed-question interface as a pattern and labels vendor performance claims unvalidated. [TypeSafe's introduction](https://docs.typesafe.ai/introduction) describes independent questions over shared state with application code composing answers; its [primitives](https://docs.typesafe.ai/primitives) accept arbitrary natural-language criteria. That flexibility is a much larger undertaking than a fixed local classifier for one codescout question. A local model can emit a typed label or ranking; it need not generate a free-form rationale. If a rationale is wanted, cited evidence spans and deterministic templates may suffice, while unconstrained prose generation is a separate component to evaluate.

Several comparative claims in the brief need correction. The [parallel-questions cookbook](https://docs.typesafe.ai/cookbooks/parallel_questions) compares one batched Jev call with separate Jev calls, not Jev with separate LLM calls. The [consistency example](https://docs.typesafe.ai/cookbooks/consistency_noul_cookbook) repeats 14 questions on one insurance claim 15 times; stable outputs there do not measure code-domain accuracy or calibration. The [reranking cookbook](https://docs.typesafe.ai/cookbooks/rerank_typesafe) concerns 40 legal queries with a BM25 shortlist, not codescout's retrieval stack. [TypeSafe's confidence description](https://docs.typesafe.ai/confidence) derives confidence from the model's output distribution; it is not an independent correctness check. The public [GitHub organization](https://github.com/typesafe-ai) exposes SDK/adapter material, which does not establish public Jev weights; we did not verify every possible commercial hosting arrangement. Marius prefers control over the system and accepts local inference or an explicitly configured external API. Pretrained open weights still carry third-party license and provenance obligations.

The brief also understates integration risk. A model may have no direct write tool and still reorder evidence, suppress a warning, induce a mistaken review, or turn a poor score into an unsafe threshold decision. Execution authority belongs to the task runtime and execution broker described in the expanded design; existing codescout access and write checks are useful foundations, not complete controls for arbitrary shell effects. Semantic scores should not confer authority. Likewise, a local small model is not automatically faster, cheaper, or better calibrated on these tasks. Those properties require measurements on the actual hardware, corpus, and failure policy.

## Bounded judgments that could support an executing agent

These are possible components or workflow triggers, not the ceiling of the product. An executing worker may gather evidence, run a discriminating probe, edit an isolated workspace, and verify a result. A fixed semantic scorer can rank or label an input; it cannot alone generate and execute a novel repair.

**1. Rank precedents and useful evidence for a new investigation.** The software can ask: given a new report or query and a fixed candidate pool, which prior records would change the next investigation step? It can return ranked artifact IDs with source excerpts and `insufficient evidence`. The [archived reconnaissance R-32 entry](../trackers/archive/reconnaissance-patterns-archived-entries.md) warns that three similarly titled catalog/path bugs had distinct mechanisms. That is a reason to retrieve candidates for reading, not to merge them or assert a shared root cause. The [usage friction U-30/U-33 records](../trackers/codescout-usage-frictions.md) and [hook H-1](../trackers/codescout-usage-hookify.md) show overlapping narratives of one command-shape mechanism; copied language and links could make a naive random split appear excellent.

Exact IDs, titles, tags, paths, citation edges, lexical search, and existing embeddings are real baselines. The [tracker-discovery evaluation](../trackers/tracker-discovery-semantic-eval.md) specified a semantic-versus-filter comparison but the inspected sections do not record its full outcome. A single smoke check after reindexing is not that comparison. A learned ranking is worth maintaining only if it puts genuinely useful precedents inside a fixed review budget more often than these baselines, without burying distinct mechanisms under superficially similar titles.

**2. Triage claims against referents or missing evidence.** The [claim-decay ledger DC-1 and DC-3](../trackers/claim-decay.md) describes concrete figures and prefix counts that became stale when their referents changed. DC-4 adds a conclusion left unchanged after maintained count/member fields moved. A bounded evaluator could flag the sentence, identify a candidate referent, and ask for a specific re-derivation. This is more distinctive than general duplicate detection because the useful output is a check to run: count bytes, enumerate declarations, compare a selector with a registry, or inspect a cited source at a revision. It must distinguish a dated snapshot from an assertion of current truth and abstain when no safe referent exists. DC-5 explicitly shows that some live tallies lack a stable fixed point.

The strongest comparator is mechanical. Explicit count-versus-membership and path predicates can catch much of this class; [DC-2](../trackers/claim-decay.md) was turned into a narrow premature-archive-citation predicate. A model is justified only for remaining indirect wording or ambiguous referents, and only if its suggested checks find more actionable drift than structural detectors at tolerable review cost. File hashes and freshness metadata can signal change, but a changed file does not make every anchored memory false, and an unchanged file does not independently verify a proposition. Codescout's [memory anchor code](../../src/memory/anchors.rs) and [librarian freshness code](../../src/librarian/freshness.rs) supply metadata, not semantic truth.

**3. Route an evidence review to the next discriminating check.** [R-101](../trackers/reconnaissance-patterns.md) records one experiment interpreted with the wrong sign: the observation distinguished rival hypotheses but was narrated as support for the one it ruled out. A review aid might compare the claim, actual observation, and explicit rival prediction, then flag apparent inconsistency or that both hypotheses predict the same result. The simpler baseline is a required counter-prediction field and a reviewer or deterministic check of its presence. Without a rival prediction and observed result, a model must abstain. This is a worthwhile hypothesis, not the chosen first pilot or a demonstrated small-encoder use case.

The same principle applies to a suspiciously complete list or a claimed contract. [IC-13](../trackers/issue-clusters/IC-13-capped-result-presented-as-complete.md) says capped output can be presented as whole; the serializer should emit truncation/continuation metadata. [IC-15](../trackers/issue-clusters/IC-15-accepted-parameter-silently-dropped.md) invites a pair of calls differing in the accepted parameter. [IC-14 and IC-18](../trackers/issue-clusters.md) ask whether a named guard or selector covers its promised population; an independent registry and a deterministic diff are stronger than a model verdict. A semantic layer might prioritize which contract to probe when prose and code use different names. It cannot infer a missing population from a capped response that never exposed one.

**Claims not established by this judgment study.** Injection screening, CI semantic linting, universal tool-call justification, model routing, and memory/tracker governance have different labels and costs. The reviewed corpus does not validate one general classifier for them, nor does this study decide which autonomous workflows should execute first. Execution should be designed separately around task capabilities, durable state, and independently observed outcomes. [Test-escape I-3/I-8](../trackers/test-escape-hardening.md) and [IC-16](../trackers/issue-clusters/IC-16-assertion-that-cannot-fail.md) show why a plausible assertion needs an executed discriminating mutation and a fixture capable of reaching the branch. [Observer-blindness OB-24/OB-26](../trackers/observer-blindness.md) shows that a precise ratio can omit the unobserved population, and a reproduction may fit multiple causes. No semantic score can reconstruct unrecorded rows or replace a probe. [U-17, U-40](../trackers/codescout-usage-frictions.md) and [TU-5/TU-7](../trackers/2026-08-15-tool-usage-investigation.md) likewise favor path rules, request-shape diagnostics, normalized error fields, and recovery-aware measurement over classification by incident frequency.

## Retrieval history is a constraint on the design

Codescout already has query embedding, candidate retrieval, optional reranking, and a fallback to original order when reranking fails in [retrieval search code](../../src/retrieval/search.rs). Current source and compose configuration reveal possible seams, not current service enablement or runtime quality. The historical [reranker issue's later clean A/B](../issues/archive/2026-07-28-reranker-costs-42x-latency-and-lowers-score.md) reported 23/75 with reranking and 26/75 without, on a 25-case suite; warm median MCP latency was 1559 ms versus 990 ms. It helped four cases and hurt five in that setup. This neither condemns all reranking nor licenses another ranker on the same data. It requires a fixed-candidate ablation and a downstream utility target.

Other historical gains came from evidence assembly. The [retrieval benchmark](../trackers/retrieval-benchmark.md) reports that filtering a code-seeking case to code moved its result from 0/3 to 3/3; the explicit source filter is deterministic, while inferring whether free-form user prose seeks code or rationale may not be. In September runs, title-bearing artifact chunks improved ordering, but re-embedding also repaired staleness, so title prefix alone was not isolated. A later `max_per_artifact` change from one to two improved hits@5 from 4/12 to 6/12 while file-hits stayed at 7/12; that is evidence for candidate diversity in that frozen run. The [chunk-grain design](../superpowers/specs/2026-09-02-artifact-chunk-grain-retrieval-design.md) documents a first-chunk-only artifact representation that could omit the answer entirely. A judge asked to score the wrong or absent chunk cannot fix that. The [oversized embedding-input bug](../issues/archive/2026-09-04-artifact-grain-sends-whole-documents-to-an-embedder-that-refuses-them.md) was addressed by segmentation, another deterministic repair. A [stale-vector diagnosis](../issues/archive/2026-09-06-chunk-reuse-key-omits-two-inputs-the-embedding-depends-on.md) was later narrowed after exercising the caller path; plausible source-level reasoning alone had overstated a live symptom.

These records imply a layered experiment: first prove candidate coverage and passage availability; then compare relevance/usefulness on identical candidates; then measure whether the presented ranking changes a real next action. “Support,” “contradict,” “duplicate,” and “useful precedent” are separate questions, not a single universal label set. The first two require a claim and evidence; duplicate compares records; usefulness depends on the investigator's task. Code-only filtering is a rule when the requested artifact kind is explicit. A model for unrestricted intent inference would be a separate question with its own labels.

## A feasible local evaluation, before model choice

The archive is valuable for reconstructing cases but is not a ready labeled dataset. The [PR-review log](../trackers/pr-review-session-log.md), specifically `pr-review-session-log:F-4` and `pr-review-session-log:W-3`, describes a passing 12-case suite and disclosed limitations alongside later executed adversarial bypasses and false positives. It is a useful case only if the pre-probe diff, report, and tests are frozen as input, and later probes are stored as outcome evidence. The record does not prove that the historical control is still broken. The [Fable review SR-4/8/9/12/15](../trackers/2026-09-01-fable-system-review.md) warns about narrow evals, unmeasured recurrence at its review date, shared-model agreement, style rewarded over utility, and the distinction between improving the product and studying methodology. We have not established whether a later recurrence metric exists.

For each prospective case, record the decision time and source revision, an immutable manifest of exact input files/passages, the permitted question and candidate set, and the later outcome separately. Exclude final diagnoses, fixes, postmortems, archive status, promoted summaries, and future citation edges from the decision-time packet. Preserve unknown and disputed labels. Keep all versions, copies, and linked reports of one incident or work-stream in one split, then test forward in time; shared author/model lineage is another possible leak. Two independent adjudicators can record disagreement, but their agreement alone does not make the target correct. Repeated model calls measure stability, not diversity.

Build negative neighbors deliberately: a dated benchmark with a valid historical number, a deliberately narrow allowlist, a top-N response that advertises its limit, a cautious incident report whose qualification is justified, and two related reports with different causes. Compare rules, exact/metadata/citation lookup, lexical search, existing dense search, a suitable local cross-encoder, and human review with the same frozen evidence. A [cross-encoder](https://sbert.net/docs/cross_encoder/usage/usage.html) is a retrieval baseline, not a calibrated verifier merely because its score can pass through a sigmoid. A candidate local backbone such as [ModernBERT-base](https://huggingface.co/answerdotai/ModernBERT-base) would still need task-specific fine-tuning and licensing/provenance review. Calibration, if needed for an action threshold, is a distinct measured property ([Guo et al.](https://proceedings.mlr.press/v70/guo17a.html)).

Success should mean more useful precedents inside a fixed reading budget, more material errors found by recommended deterministic follow-ups, or fewer wasted investigations at an acceptable miss rate. Report candidate recall separately from judgment quality, latency and resource use on the actual local hardware, abstentions and false positives, and behavior when inference is unavailable. A model that scores well on archive language but does not alter a correct next step has not met the product test. If time-frozen inputs or credible outcomes cannot be assembled, the learned experiment should stop at dataset construction.

## Handoff to the execution design

This study supplies candidate evidence tasks and non-model baselines for the [deep-agent design](../trackers/local-semantic-evaluator-design.md). The next architectural decisions are the first authorized substantive workflow and independent completion oracle; the task/event/capability contract; how codescout's pre/post context coordinator supplies evidence at the right phase; and a provider-neutral worker loop using local inference or an explicitly configured API. Historical retrieval and classifier observations should be evaluated as components of that full loop, not used as a blanket advisory-only limit. No model or implementation was selected by this study, and no autonomous benchmark was run.
