# Un-anchored blast-radius eval — design

**Status:** draft, awaiting review. No code written.

**Supersedes in intent, not in file:**
[`2026-08-23-hidden-information-eval-design.md`](2026-08-23-hidden-information-eval-design.md)

## 1. Why the current eval cannot answer the question

The hidden-information eval asks *"find every place that reads the tax rate."* Eight
rounds in it does not discriminate, and the reason is structural rather than fixable
by tuning:

- **Recall sits at 1.0000 in 11 of 12 round-7 runs.** The dimension a navigation tool
  could move is at ceiling.
- **The instrument has three values.** All twelve round-7 runs produced exactly three
  distinct F1 scores spanning **0.046**, against a separation gate of 0.10. Every
  per-run value lies in [0.8000, 0.8462], so every arm *mean* does too: the F1 limb of
  gate 4 is unreachable at any sample size.
- **The cause is anchoring.** Naming the target supplies the doubt that was absent in
  every recorded real failure. The same needle-in-a-haystack harness was run on this
  machine before and saturated identically: five blind subagents, **5/5 exact** on
  name + value + `path:line`, zero line drift, 5/5 correctly CERTAIN, mean 5.8 tool
  calls. The conclusion recorded then — *"Retrieval is healthy; triggering retrieval
  is what's broken"* — is the finding this spec is built on.
- **The failure population is the inverse of what recall scores.** Of 51 failures
  reconstructed from real session transcripts: **36 confident wrong answers, 4 pure
  misses**, and **0** caught by unaided self-review.

Anchored + findable ceilings. Anchored + unfindable floors — twelve agents once
unanimously and *correctly* declined an impossible band. There is no discriminating
middle inside the anchored paradigm, so no negative test can be built there.

## 2. The design in one paragraph

Give the agent a narrow, real bug. Fixing it correctly requires editing a **shared**
function. Nothing in the prompt says the function is shared, who depends on it, or
that impact analysis is expected. Score three things separately: whether the agent
asked what depends on it, how completely it enumerated the dependents, and whether the
shipped fix silently moved outputs it never mentioned.

The sub-goal — *"…who else calls this?"* — must be generated by the work, never by the
prompt.

## 3. The defect

`src/intl/duties.py` today (`gen_fixture.py:1355-1358`):

```python
from src.pricing.basis import BASIS_POINTS_PER_UNIT, _rate_bp


def duty_multiplier() -> float:
    """Multiplier applied for import duty."""
    return 1 + _rate_bp() / BASIS_POINTS_PER_UNIT
```

The planted defect is a **single character**: `/` becomes `//`.

```python
    return 1 + _rate_bp() // BASIS_POINTS_PER_UNIT      # 825 // 10000 == 0
```

`duty_multiplier()` returns `1.0` instead of `1.0825`. Import duty is silently never
applied.

Three properties make this the right defect:

1. **The fix necessarily changes the return value.** There is no local workaround, no
   way to patch the symptom downstream, and no fix that leaves dependents untouched.
2. **It is a genuine Python footgun**, not a contrivance, so the agent gets no
   meta-signal that it is being tested.
3. **The fix is one character.** That is the point. A one-character edit invites no
   impact analysis, so what the eval measures is unprompted suspicion rather than
   diligence proportional to a large diff.

**The prompt** — this is the entire task, no other hint is given:

> Cross-border orders aren't being charged import duty — `international_total` comes
> back equal to the plain subtotal. Fix it.

Naming the symptom is not anchoring; a bug report has to say what is wrong. What is
never named is the dependency set, which is the thing under measurement.

## 4. The six dependents

`duty_multiplier` currently has **two** direct consumers. Four are added, and the
selection principle is that all six use **different reference forms**, so no single
lexical pattern enumerates them — and that the set is **balanced** between forms each
toolchain misses.

| # | file | form | LSP `references` | grep `duty_multiplier` |
|---|---|---|---|---|
| 1 | `src/intl/customs.py` *(exists)* | import-time module cache — `LEVY_MULTIPLIER = duty_multiplier()` | ✓ | ✓ |
| 2 | `src/intl/checkout.py` *(exists)* | plain import + call — `describe_duty()` | ✓ | ✓ |
| 3 | `src/intl/manifest.py` *(new)* | aliased import — `… import duty_multiplier as _dm`, called `_dm()` | ✓ | **✗ at the call site** |
| 4 | `src/orders/crossborder.py` *(new)* | package re-export — `from src.intl import duty_multiplier` | ✓ | **✗ — caller names the package** |
| 5 | `src/pricing/registry.py` *(new)* | string in a dict — `getattr(_duties, RATE_FNS["duty"])()` | **✗ — no symbol reference exists** | ✓ |
| 6 | `src/exports/customs_feed.py` *(new)* | name in `pricing.toml`, dispatched at runtime | **✗** | ✓ **only if non-`.py` files are searched** |

**Balance is 2 / 2 / 2**: two forms both toolchains find, two only LSP finds, two only
a lexical search finds. **Neither toolchain reaches 6/6 alone**, and neither is
favoured by the set's construction.

Rows 5 and 6 are the most important rows in this spec. **They are the ones codescout
loses**, and they use two *different* mechanisms rather than the same trick twice, so
one implementation slip does not decide the codescout-loses case. An eval in which the
tool under test can only win is an advertisement, not a measurement: a `getattr`
lookup and a config-file dispatch are both invisible to LSP and both findable by a
lexical sweep, so the native arm has real points available to it and a codescout win
becomes worth believing.

Row 6 carries an extra property worth stating: it is findable **only by an agent that
searches beyond `*.py`**. That is itself a recorded failure — a grep whose default
scope silently excluded the file containing the answer returned **`0 matches` on four
separate probes**, including one naming the file's exact path as its glob.

Rows 3 and 4 are the mirror: forms where a grep-driven enumeration silently
undercounts. This reproduces a recorded failure exactly — a regex sweep counted **13
construction sites where reality was ~30**, because it matched once per line rather
than once per occurrence.

**Dropped from the earlier draft:** the module-attribute form
(`import src.intl.duties as duties` … `duties.duty_multiplier()`). Both toolchains
find it, and rows 1–2 already cover that case; a third both-find row adds cost and no
discrimination.

### 4a. Anti-oracle requirement (blocking)

Six files sharing one import is itself a signature. The fixture's own band-C design
already states the rule: *"exactly ONE band-C file names `TAX_RATE`. If all four did,
'imports `src/config/rates.py`' would select 8 of 12 truth sites and become an
oracle."*

**For each of the six reference forms, plant at least two filler files using the same
form against a different, unrelated function.** The form must not be the signal. This
is a build-time assertion in the generator, not a review note.

For row 6 this extends to the config file: `pricing.toml` must name several functions,
only one of which is `duty_multiplier`, or "appears in `pricing.toml`" becomes the
oracle.
## 5. Scoring — three links, measured separately

The sub-goal is a chain and each link fails differently. Collapsing them into one
number would hide which one broke.

| link | metric | range | tool-sensitive? |
|---|---|---|---|
| **L0** | `fix_correct` — does `international_total` now apply duty? | 0–1 | no |
| **L1** | `asked` — did any tool call target `duty_multiplier`'s dependents? | 0–1 | probably not |
| **L2** | `enumerated` — how many of the six were reached | 0–6 | **yes, strongly** |
| **L3** | `silent_changes` — outputs that moved and were never mentioned | 0–6 | yes |

(`disclosed` is recorded alongside, from the answer text: `silent_changes = changed − disclosed`.)

**L2 is the primary between-arm comparison.** It is where the toolchains genuinely
differ, and it has seven possible values rather than three — the resolution the current
instrument lacks.

**"Reached" is defined from the TRACE, not the answer text.** A dependent counts as
enumerated when the run either (a) opened its file, or (b) received it in the result of
a call naming `duty_multiplier`. It does **not** count merely because the final answer
mentions it. Two reasons: an answer can name a file the run never looked at, which is
the confident-wrong-answer shape this whole eval exists to catch; and scoring the
answer text would reintroduce exactly the list-shaped, prompt-shaped metric that
saturated the current instrument. `disclosed` — how many the answer *names* — is
recorded separately, and `disclosed > enumerated` is itself a finding worth surfacing.

**L1's detector must be pre-registered and symmetric.** Both idioms count, or the
metric is arm-asymmetric by construction:

- cs family: `references(duty_multiplier)`, `call_graph(duty_multiplier)`,
  `symbols(name="duty_multiplier")`, `grep("duty_multiplier")`, or reading any of the
  six dependent files.
- native family: `Grep` naming `duty_multiplier`, a `Bash` invocation of
  `grep`/`rg`/`ag` naming it, or `Read` of any of the six dependent files.

**L3 needs no authored answer key.** The fixture's own pre-edit behaviour is the ground
truth. A harness imports every entry point, records its value before the run, and
re-records after. The defect class that has now bitten this project twice — R-31's
impossible band C, and `RATE_BASIS_POINTS` scored a false positive while literally
reading `TAX_RATE` — is a hand-authored-key defect and **cannot recur under a
behavioural check.**

### 5a. The golden-output fingerprint

After a correct and complete fix:

| output | must |
|---|---|
| `international_total`, `apply_levy` | **change** — that is the bug |
| the six dependents' outputs | change, **and be disclosed** |
| `surcharge_label`, `rate_basis_points_label` | **not change** — different branch of the chain |
| band A / band B totals | **not change** |

A run that moves the last two groups has broken something and is scored as such.

## 6. The planted belief

Ship a test suite that covers `apply_levy` and **not** the six dependents. Green then
reads as done while several outputs have silently moved.

This is a recorded failure shape, not a hypothesis: *"a flag set from prose, and 43
tests passed on it"*, and *"a green suite and a red one are equally uninformative
here."* It costs one file and it is the cheapest belief-plant available.

## 7. Arms

Five arms. Directory grouping follows the existing constraint: `run_arms.py` scores
every arm in a directory with the **first** arm's checker, and `disallowed_tools` is
read per-directory, so each directory holds arms sharing both.

| directory | arm | denied | purpose |
|---|---|---|---|
| `bugfix-cs` | `blast-cs` | native tools + `Agent` | codescout MCP only |
| `bugfix-native` | `blast-native` | `Agent` | native tools |
| `bugfix-pos-cs` | `blast-pos-cs` | native tools + `Agent` | prompt adds *"before changing anything shared, enumerate what depends on it"* |
| `bugfix-pos-native` | `blast-pos-native` | `Agent` | same hint, native |
| `notools` *(reused)* | `no-tools` | 19 names | floor |

The positive controls target **L1**, the link with no baseline otherwise. If a hinted
arm does not show `asked=1` and a high `enumerated`, the trace detector is broken and
no reading from L2 means anything — the same job gate 2 does today, aimed at the
constraint that actually binds here.

`no-tools` cannot edit files, so it scores L0=0 trivially. It is retained as a cheap
sanity check and may be dropped if it proves uninformative.

## 8. Gates

1. **Calibrated** — `fix_correct` is 1 in most runs of both main arms. If agents
   cannot fix the bug at all, nothing downstream is interpretable.
2. **Positive control** — both hinted arms reach `asked=1` and `enumerated >= 5`.
3. **Detector symmetry** — on a run with high `enumerated`, the detector fired on both
   families' idioms. Asserted against the pre-registered list, not assumed.
4. **Separation** — `enumerated` differs between `blast-cs` and `blast-native`.
   Threshold deliberately **not fixed in this spec**; see §10.
5. **Floor** — `no-tools` scores L0=0.

Every gate refuses rather than reports when any of its arms has an `indeterminate:*`
run, exactly as `gates.py` does today.

## 9. Honest limits

Stated here rather than discovered later.

- **Reading is not seeing.** Opening a dependent file counts as `asked` even if the
  agent read past the dependency. The sharpest episode in the evidence corpus is
  exactly this: a fact **fifteen lines below the agent's own cursor**, in a file it had
  already read, missed because *"I was reading for the claim I'd come to fix, not for
  what the file already knew."* L1 will score that as a hit. A ceiling on the metric,
  not a bug in it.
- **A right answer by a wrong route is invisible to L3.** Behavioural scoring cannot
  see *why* a fix was correct.
- **Non-determinism is higher than in the current eval.** A bug fix has many valid
  shapes; L3 tolerates that by construction, L2 does not.
- **Every addition is a leak channel.** Six new hand-authored files plus a test suite
  plus a harness. The 75-predicate / 140,675-combination sweep must grow to include the
  reference-form predicates and re-run **after each change**, not once at the end. A
  mis-calibrated predicate once sat undetected for three rounds inside every
  worst-surviving combination while never tripping a verdict alone.
- **The arms write to disk.** Each run already untars into a fresh temp directory, so
  contamination between runs is handled — but this eval now measures editing capability
  alongside search, which is a genuine widening of scope.
- **n=2 pilots can only falsify the instrument, never measure an effect.** Rounds 7 and
  8 both demonstrated this. Any separation reading needs power, and §10 does not pretend
  otherwise.

## 10. What this spec deliberately does not decide

- **Gate 4's threshold.** Setting a separation bar before seeing the support is what
  produced an unreachable gate last time. The first pilot's job is to establish the
  achievable range of `enumerated`; the threshold is set afterwards, from that range,
  and recorded as a ruling.
- **Sample size.** Follows from the observed spread, not from a guess.
- **Whether the `## UNCERTAIN` calibration contract (F-14) carries over.** It measurably
  changed what agents listed in the current eval — `SAMPLE_RATE` went 0/4 to 4/4 — so it
  is not free, and it should be piloted here separately rather than inherited.
- **The fate of the existing hidden-information eval.** Untouched by this spec.

## 11. Build order

1. Extend `gen_fixture.py`: the defect, the four new dependents, the anti-oracle filler
   for all six forms, the partial test suite. Regenerate; pin new hashes.
2. Grow the leak sweep with reference-form predicates; run it; fix what leaks; repeat
   until clean.
3. Write the golden-output harness and its own tests.
4. Write `check_blast.py`: L0–L3, the pre-registered detector lists, and the
   `indeterminate:*` classes carried over unchanged.
5. Generate arms; assert the prompt is byte-identical across families.
6. Mutation-test the checker before any paid run — each mutation naming what must break
   **and** what must survive.
7. Pilot the two positive controls first. If the detector cannot see a hinted arm, stop:
   nothing else is interpretable.
8. Then pilot the main arms, read the support, set the threshold, record the ruling.

## Review checklist for the reader

The four questions this draft opened were **decided on 2026-08-25** rather than left
open. Each is reversible; the reasoning is recorded so a reversal is informed.

1. **Defect — integer truncation, not a rounding error.** Truncation gives an 8.25%
   swing and an unambiguous symptom. A rounding error (`1.08` vs `1.0825`) is more
   realistic but its symptom is arguable, and `fix_correct` (L0) gates every other
   metric — an arguable L0 makes the whole run uninterpretable. Subtlety belongs in the
   blast radius, which is already subtle.
2. **Six dependents — kept**, for the resolution argument in §5: a set of two makes
   "did you find them" a coin flip, and the undercount failure mode this eval targets
   is undetectable on two.
3. **Rows 5 and 6 — the earlier draft had ONE LSP-invisible form against TWO
   grep-invisible ones**, so the set leaned toward codescout before a single run. Now
   balanced 2/2/2, with the two LSP-invisible rows using different mechanisms so one
   implementation slip does not decide the case. The module-attribute form was dropped
   to make room.
4. **Positive control for BOTH families — a correctness requirement, not a budget
   one.** The L1 detector is per-family and the two families' tool idioms differ, so a
   cs-only control cannot validate the native detector.
